# Route Proposal

Prefer the user's explicit objective. If absent, present at most three
evidence-backed candidates and wait for selection. Inspect current source/tests,
contracts/architecture, plans and relevant memory; use the preparation skill's
readiness framework where it informs this route.

Model milestones, work items, decisions, evidence/reference prerequisites and
lanes as a DAG. Report exact baseline/Epoch, one objective and observable success,
architecture/activation/maturity/release evidence, critical path, lane order,
keep/reorder/rewrite/delete dispositions, immediate/deferred decisions,
affected owners, residual scans and validation.

Use `scripts/check_route_proposal.py` through clean Nix. Confirmation binds
proposal, clean context, HEAD and Epoch; changed evidence requires re-audit.
Preserve completed work. Reorder active/queued nodes only in the confirmed
Epoch; retain IDs when delivery coordinates and outputs stay the same.
